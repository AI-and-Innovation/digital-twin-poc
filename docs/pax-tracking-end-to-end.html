Passenger tracking, end to end

RGIA Terminal 1. One synthetic simulation produces four flat JSON feeds. Kafka carries them. The local dashboard and Esri both read the same records. All passengers are synthetic. The building outline is OpenStreetMap. Floors, counters, and paths inside it are schematic.

Two ways to look at it. scripts/local_poc.sh map draws the simulation straight into http://127.0.0.1:8080. The header says in-process simulation. scripts/local_poc.sh demo publishes the same records to Kafka and the page reads those topics. The header then says Live - kafka localhost:9092. The file sample is AirportEye-pax-tracking-sample.zip.

Architecture

1 · Simulation

Flights, then people

  • Six journey streams from config
  • Each person walks, queues, is served
  • One shared line per checkpoint
→
2 · Flat JSON

One object per record

  • No nested payload
  • Track id entity_id
  • Time event_time_epoch_ms
  • X/Y longitude / latitude
  • Z elevation_m
→
3 · Kafka

Four topics

  • Position every 5 s
  • Queue, zone, journey every minute
  • Key HYD:<entity_id>
  • acks=all, lz4
→
4 · Readers

Same records

  • Dashboard at :8080
  • ArcGIS Velocity or GeoEvent
  • Or the zip, with no broker

Code: generators/passenger.py builds the people. esri.py flattens each event. publishers/kafka.py sends it. scripts/map_viewer.py and scripts/viewer/index.html draw it.

What is simulated

1. Flights
A rate per hour, thinned by the local hour so morning and evening are busy. Id looks like SYN-DD0001. A departure gets a gate. That gate stays busy for 50 minutes.
2. Passengers
Departures appear at the kerb before the flight. Arrivals come off buses of 60, first bus 4 minutes after landing, then every 3 minutes. Id SYN-PAX-000001.
3. Path
Entry, check-in or skip, security, emigration if international, then gate. Arrivals do immigration, reclaim, exit. Shares in config pick DigiYatra, kiosk, web check-in, e-gate.
4. Queue
One FIFO line. An open lane takes the person at the front and draws a service time. queue_length is people still waiting. People at a counter are in_service.

Lanes

Installed count is in config/hyderabad_touchpoints.json. Lanes actually open are open_channels in config/passenger_tracking.json. A checkpoint missing from that list uses every installed lane. Each gate has its own queue of 2 lanes, 5–12 seconds. The boarding row on the page is the sum of those gates.

If the open lanes finish people as fast as they arrive, queue_length stays 0 and the people you still see are in service. That is the waiting line being empty, not a stopped feed.

The four feeds

passenger.position

Every 5 seconds, one passenger

The moving dot. activity is walking, queuing, in_service, dwelling, at_gate, reclaim, then boarded or exited. longitude, latitude, floor, elevation_m and indoor_z (the same height).

passenger.touchpoint

Every minute, 16 checkpoints

The white popup. Queue, lanes open, in service, estimated wait, measured wait, processing time, throughput since local midnight, status. The point is the checkpoint, not the passenger.

passenger.aggregate

Every minute, one zone

People, density per 100 m², and what they are doing. longitude / latitude are the zone centre. cells is a JSON string of 5 m grid counts.

passenger.journey_kpi

Every minute, one terminal row

entity_id is HYD-T1-JOURNEYS. People in the terminal, kerb-to-airside, airside-to-boarding, arrival-to-exit, longest wait. No latitude, longitude, or height.

JSON Esri receives

One flat object per Kafka message. Do not send the nested files under samples/. Those still wrap a payload.

Heights. elevation_m is local Z above the terminal ground floor (0 on L0, 8 on L1). reference_elevation_m is REFERENCE_Z for L0 / the local origin (POC: 617 m approx AMSL for RGIA, replace with your survey). global_elevation_m = reference + local, for a global 3D scene. Located records also carry web_mercator_x / web_mercator_y (EPSG:3857).

Local broker is localhost:9092 from config/poc.json. That address only works on this laptop. Esri can use their own cluster:

export KAFKA_BOOTSTRAP_SERVERS=<their-host:port>
export KAFKA_SECURITY_PROTOCOL=SASL_SSL
export KAFKA_SASL_MECHANISM=PLAIN
export KAFKA_SASL_USERNAME=<user>
export KAFKA_SASL_PASSWORD=<password>
scripts/local_poc.sh pax

Messages are lz4. Their consumer has to accept lz4. This path has not been run against a live ArcGIS Velocity or GeoEvent feed yet.

What the page shows

http://127.0.0.1:8080

  • Top tiles are the journey record.
  • Dots are position records. Click one for that passenger.
  • A checkpoint row opens the white box: queue, open lanes, in service, waits, processing time, and the 60-minute chart. It stays open and updates.
  • Zoomed in, grey blocks are the open lanes and the coloured area is the line.
  • Zones tab is the aggregate feed.
  • 3D view stacks L0 at 0 m and L1 at 8 m.
